01 — Why

Five products, five shades of blue, zero shared parts

By 2024, Ionex was shipping web consoles and apps for energy operations, fleet rental, riders, field maintenance, and dealers. Each team had drifted: the same button existed in five codebases with five paddings, and "primary blue" meant a slightly different hex everywhere.

Every new feature paid a redundancy tax — designers redrew basics, engineers re-implemented them, and QA re-tested them. IonexOS is the shared foundation that ended that tax: one set of tokens, one component library, one place where the truth lives.

02 — Foundations

Tokens first: semantic names, two themes, one source

Colors are defined as primitives, then mapped to semantic tokens (primary, surface, success, error…) that resolve differently in light and dark themes. Products never touch raw hex values — they speak in meaning, and the theme decides the color.

03 — Pipeline

From Figma Variables to shipped code, without a game of telephone

The system's credibility depends on design and code never drifting apart. Tokens are authored once in Figma Variables and flow downstream mechanically:

1.

Figma Variables

Designers manage primitives and semantic tokens with light/dark modes in the IonexOS WebKit library.

2.

Token files

Variables sync into src/tokens/*.ts — colors, typography, shadows, spacing, radius.

3.

Themed components

Components read only from the theme — theme.semantic.* — hardcoded values are banned by convention and review.

4.

Storybook docs

Every component ships with autodocs, a Playground story, and an AllVariants overview — the docs are the contract.

05 — Governance

A system is a product with two audiences

a.

For designers

The Figma library mirrors the code library one-to-one — variants, states, and tokens included — so a mock-up is already a spec.

b.

For engineers

Strict TypeScript, one folder per component, styles only from theme values. Storybook is both workbench and documentation.

c.

Contribution loop

Product teams propose patterns from real needs; validated ones graduate into the system — the library grows from evidence, not speculation.

d.

Versioned releases

WebKit versions (v1.8 and counting) keep Figma and code in lockstep, with a roadmap tracking every phase from foundations to data patterns.
